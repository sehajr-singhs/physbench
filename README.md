# PhysBench

> **Most physics-ML benchmarks validate the model against the *same* code
> that generated the data — so agreement can just mean shared bugs. PhysBench
> scores every prediction against an independent governing-equation
> verifier, and the ground truth is generated separately from the training
> signal.**

A verifiable multi-domain benchmark for physics-informed machine learning:
twelve domains — algebraic closed-form trajectories, energy conservation,
harmonic/relaxation ODEs (spring, LC, damped oscillator), central-force
motion (Kepler), fourth-order bending (beam, cantilever), linear drag, a
conservation-law PDE (Burgers), and an elliptic field problem (heat plate).

**Paper:** [manuscript.pdf](manuscript.pdf) · [supplementary
information](supplementary_information.pdf). Every number in the paper reads
from a committed JSON under `physx/models/matrix/` and `figs/`.

## The independent-verifier principle

Two independence conditions, both structural:

1. **Targets are generated separately from the training signal.** Every
   target comes from a closed-form solution or a high-resolution numerical
   integrator implemented independently of the data generator the models
   train on.
2. **Predictions are scored against the governing equation, not the
   generating code.** A predicted trajectory's curve error is one thing; its
   governing-equation residual — how far it violates the actual physics — is
   checked by a verifier written from scratch, in a different formulation
   (finite differences, Euler/RK4, energy balance).

That is what makes a benchmark claim survive contact with a reviewer: "this
model got the answer right" is only meaningful if "right" is defined by
something the benchmark author did not also write.

## Measured results (nothing extrapolated)

| Result | Number |
|---|---|
| Baseline matrix | 75 runs (5 domains × 3 architectures × 5 seeds), fully committed |
| Difficulty span | held-out error spans ~2 orders of magnitude across domains |
| Best architecture | differs by domain (no universal winner — that is the point) |
| Operator comparison | 10 dedicated DeepONets: median 0.037 vs. single generalist 0.110 |
| Generalist wins outright | spring (0.111 vs 0.122) and LC (0.100 vs 0.192) |

## Reproduce

```bash
pip install -r requirements.txt
python -m unittest tests.test_physx       # 49 tests, all green

# regenerate every figure from committed data
python figs/make_figures.py

# re-aggregate the 75-run matrix from the committed stats files
python figs/agg_matrix.py

# re-run the matrix (under an hour on a 20-core CPU)
python src/physx/run_matrix.py

# re-run the DeepONet per-law baselines
python src/physx/baselines.py --per-law-only
```

## Honest scope

PhysBench is small by design — a few hundred samples per domain, CPU-minutes
of training. It is built to expose *mechanisms* (when physics supervision
helps, when it merely enforces consistency) rather than to win leaderboards.
Every instance is generated by this project's own simulator; external
adoption is the benchmark's real test, and the open data generator is the
invitation.
